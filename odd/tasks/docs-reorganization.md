## Context

The user asked whether every repository `.md` carrying project information should live under `docs/`.
Audit of the tracked `.md` files on `main` produced the classification below.

`docs/` already existed with two files (`backend-requirements.md`, `endpoints.md`) from commit `c75f5567`
("docs: reconcile the repository docs with the delivered app"), so this work finishes a convention that
was already started, not a new one.

contract and mix history with documentation.

### Naming decision

`docs/` already uses lowercase kebab-case English filenames (`backend-requirements.md`,
`endpoints.md`). The moved project docs adopt the same convention (`routes.md`,
`project-structure.md`, `decisions/vite-decision.md`) while keeping their Spanish **content**
untouched. The two original input documents under `docs/requisitos/` keep their original filenames:
they are historical evidence (a handoff spec and a superseded plan) referenced by `cite:` keys and by
the `odd/` task records, so renaming them would destroy traceability.

### Accepted consequences

- Root-level links to `ROUTES.md` and `VITE_DECISION.md` from outside the repository (PR comments, other
  repos) break. No redirect stubs are added; the repository keeps one copy of each document.
- `odd/tasks/*.md` keep their historical `assets/...` and `ROUTES.md` paths on purpose: those files
  record what was true when the task closed, and rewriting them would falsify the record.

### Findings that changed this record

1. **My evidence for the `oddf` deletion was wrong and is now corrected.** I had written that
   `odd/tasks/frontend-rtk-query.md` referenced the orphan file. The direction is the opposite: the deleted
   file pointed at that task record, and nothing pointed at it. The deletion is *safer* than I claimed, but
   the recorded reason was inverted.
2. **Staging state is a blocker for committing as-is.** `git mv`/`git rm` staged the renames and deletions,
   while the content edits are unstaged: `git diff --cached --numstat HEAD` shows `0 0` for
   `docs/project-structure.md` and `docs/decisions/vite-decision.md`. A bare `git commit` right now would
   record the moves carrying their **`HEAD` content**, i.e. a `docs/project-structure.md` still advertising
   `assets/` and a `vite-decision.md` still pointing at root paths. Everything must be `git add`ed first.
3. **Cosmetic, introduced by this change:** the new `docs/` comment in the tree diagram is far longer than
   every other comment, so it breaks the comment-column alignment. The tree characters themselves still line
   up. Left as-is on purpose: any further edit invalidates the independent verification above.

## Decisions

- **`docs/` is the documentation home; the root keeps only platform-recognized and tool-owned files.**
- **Do not move `odd/tasks/`.** Workflow state is not documentation.
- **Do not rewrite historical records** (`odd/tasks/*.md`) to follow the new paths.
- **Preserve the original filenames of the two input documents.** Historical evidence keeps its name.
- **Nothing is committed.** The commit is a separate, user-owned decision, and it requires staging first
  (finding 2 above).
- **The pre-existing defects are follow-ups, not scope creep.** Fixing stale content is a different change
  with its own review cost, so it is reported rather than absorbed.
- **The verified artifact is the tree as it stands.** No polish edit is applied after verification, even for
  the cosmetic finding 3.
